# scripts/dashboard.js — Home screen

Exports: `ScreenDashboard`, `ScreenFood`, `MiniCalendarCard`, `HOME_WIDGETS`,
`resolveHomeLayout` (check the export block for the exact list).

Every card is a plain function taking a props object and returning DOM. `ScreenDashboard`
assembles them in the user's saved widget order; `resolveHomeLayout(saved)` reconciles the
saved layout against `HOME_WIDGETS` so a new widget appears and a removed one vanishes
without migration. Persisted by `saveHomeLayout` in app.js. Both live in **`scripts/home-order.js`**
(DOM-free, re-exported here) with Home's ordering rules — `sortTasksForHome`, `sortHabitsForHome`,
`habitDue`, `topStreaks`, `homeGoals` — checked by `node scripts/home-order.test.mjs`.

**What Home actually renders** (the `renderers` map, one per `HOME_WIDGETS` id): `score` →
`ScoreCard`, `outlook` → `OutlookCard` (outlook-card.js over outlook.js: the top insights.js card with its dismiss x and action, then savings / streak pace; dismissals share Report's `uiPrefs.insightsDismissed`; no history fetch on Home), `plan` → `TodayPlanCard`, `wellness` → `WellnessCard`, `tasks` → `TasksCard`,
`calendar` → `MiniCalendarCard`, `habits` → `HabitStrip`, `goals` → `GoalsCard`, `money` →
`MoneyHomeCard` (money-home.js; without a budget the figure reads "spent so far this month" and the week sentence has no eyebrow; carries the repeat-expense "Add it?" nudge, `repeatExpense` in nudges.js, Not today dismisses in memory), `reminders` → `ReminderSuggestionsCard`; plus `OnboardingCard` on top.
`QuoteCard`, `WeeklyReflectionCard`, `BadgeCard`, `GoalTimelineCard` and `HabitSleepInsightCard`
are defined and exported here but rendered elsewhere (Report, the Habits screen, the quote slot in
app.js); `WaterCard` / `FoodCard` belong to `ScreenFood`.

**First run short-circuits the whole layout:** with no data of any kind yet (tasks, habits,
reminders, money entries, food, water, mood or sleep), `ScreenDashboard` returns the
`OnboardingCard` alone (`.gb-dash--onboarding` centres it, on desktop too). Every widget renders its
own "nothing yet" state, so a new account used to open on nine empty cards saying the same thing
three ways. Adding anything — or dismissing the checklist — brings the full Home back.

**The Quick add bar is always first and is not a widget.** The `quickAdd` prop (app.js's
`homeQuickAdd()`, the same `quickAddBox()` the + sheet uses) is wrapped in a `Card` as
`.gb-dash-qa` and put above everything, the onboarding-only Home included. It stays out of
`HOME_WIDGETS` on purpose, so the layout editor can't hide or reorder it. Null prop = no bar.

| Card | Notes |
|---|---|
| `OnboardingCard` | first-run checklist; each step marks itself done from real data (mood: any mood ever, not today's), and only the steps still left are listed under an "N of M done" title. Its first step, "Pick a goal, we set it up", is `onStarterPack` (→ `openStarterPacks` in app.js) and is left out when that prop is absent. Dismissal key `gb.onboardDismissed`; the ✕ calls `onOnboardDismiss({ rerender: true })` so a fresh account (checklist = whole Home) re-renders instead of going blank. The all-done path calls it bare on purpose: it runs mid-render (a re-render from there would nest), and an all-done account already has data, so the full Home renders anyway |
| `ScoreCard` | today's completion ring. Tasks are `tasksForToday` (home-order.js, shared with app.js `score()`): due by tonight or done today; with none but open ones later, the sub-line reads "Nothing due today". When the one-thing card is a streak (`streakAsked`) the heading counts what's left ("3 things left today") instead of repeating "Keep your 6-day run going". The `%` lives in the number (`100%` over `SCORE`), matching Progress's summary tile and its "Daily score" trend — one number, one name. The sub-line (`4/4 tasks · 3/3 habits`) is the percentage's own arithmetic: habits are only the ones **owed today** (`habitDue`, the server's `dueToday` — a weekly habit already met this week, or a paused one, is not today's miss), same rule as `HabitService.countsOn`. The streak pill is split by unit (`topStreaks`): `N-day` for daily habits, `N-week` for weekly / N-a-week ones. No level/XP pill: different currency, lives in the profile menu. |
| `GoalsCard` | the `goals` widget: up to 3 open goals, nearest target first (`homeGoals`), each with days left / overdue, the next unticked milestone and the day tracker's count from `goalProgress` (app.js passes `effectiveGoalProgress()`, so a tracker counting from linked habits shows that count). Every row opens Goals (`onOpenGoals`); nothing is edited here |
| `TaskRow` / `TasksCard` | titled "Tasks" (it carries tomorrow's and undated ones too, so "Today's tasks" was wrong), `PRIORITY` colors, ordered by `sortTasksForHome` (overdue → today → upcoming → no date, paused and done last). The sub line is `taskWhen` (home-order.js: "2 days overdue", "Overdue · 18:42", "Today 10:00", "Tomorrow 10:00") for an open task, mapTask's `task.time` for a done one, in a nowrap `.gb-task-when` (coral when `task.overdue`); the priority pill wraps under it on a phone. The trailing `.gb-icon-btn` pencil is the only way to edit a task — it calls `onEditTask` (app.js `openEditTask`) and is skipped when that prop is absent. A timer button before it (`onFocusTask`, app.js `startFocusOn({taskId})`, null when the Focus feature is off; not on done/paused rows) opens Focus with the task picked. The list grows with the page (no inner scroll box); past `TASKS_SHOWN` (6) a "Show all" button opens the rest in place (`tasksExpanded`, module-level) |
| `HabitCard` / `HabitStrip` | habit check-ins, ordered by `sortHabitsForHome` (owed and unticked first, then not owed today, done, paused). The flame + number carries an `aria-label` ("5-day streak" / "3-week streak") |
| `QuoteCard` | quote of the day (cached per day in app.js); not a Home widget |
| `OneThingCard` | pinned above the layout, right under the Quick add bar (not a widget; `HOME_WIDGETS` and saved layouts never see it, and the onboarding-only Home skips it): kicker "One thing today", the title and why from `pickOneThing` (one-thing.js), and one button that calls the existing handler for that kind (`toggleHabit`, `toggleTask`, `onOpenMoney`, `onConfirmSleep`, `onQuickAddWater`, `onAddMood`). A kind with no handler is skipped; null → no card. The next render re-picks. `oneThingFor` picks it at the top of `ScreenDashboard`, so when the card is asking for sleep or mood, `WellnessQuick`'s row for the same thing is dropped, so is `TodayPlanCard`'s chip for it, and so is the Sleep/Mood tile while it is still unlogged (no nudge twice). While Getting started still lists "Log how you feel", `oneThingFor` passes `skipKinds: ['mood']` (so the checklist is computed first). Water is a candidate only with a non-empty `waterUsualHours` prop (app.js, from /api/water/times) or water logged today. Its block is `.gb-dash-pin`: with `.gb-dash-qa` it spans both desktop columns. |
| `TodayPlanCard` | the "Plan my day" action (opens `openDailyPlan`: a no-AI draft from `day-plan.js`, see CODEMAP) plus chips for **what's still open**. Three rules: it never repeats the score ring (which owns tasks + habits), it drops a chip another card already asks (`skip`, a list: the one-thing card's kind; sleep + mood whenever the `wellness` widget is enabled on Home; mood while the Getting started checklist still lists "Log how you feel"), and it never congratulates — a "Sleep logged" chip sitting above a card reading "7.5h · Good" said less than the thing beneath it. Everything done → the chip row doesn't render. |
| `WellnessCard` | sleep + mood entry points (a lone tile spans the row); `sleepHours(entry)`. Above the tiles, `WellnessQuick`: "Slept 23:10 to 06:50?" Yes / Edit (`sleepToConfirm` over `lastNightGuess`, nudges.js, the same call the one-thing card makes: the phone's night (`phoneNight` prop, copy "Your phone logged 23:10 to 06:45. Save it?", shown at once), else the usual, else the last logged night; the non-phone ones only once that wake time has passed; Yes → `onConfirmSleep(guess)` with its quality, Edit → the sleep dialog) and the mood scale as four buttons (`onQuickMood(value)`); each row goes once its entry exists. One ask each: an unlogged tile is hidden while its check-in row (or the one-thing card, `asked`) asks the same thing; a logged tile shows the value. Sub-labels are sentence case from JS (`sentence`), not CSS; no energy line when the entry has none (note: app.js `saveMoodEntry` defaults a quick mood's energy to 'medium', so that line still shows until it stops) |
| `WeeklyReflectionCard` | nudge into the weekly review — rendered on Report, not Home. Week counts: tasks done in the last 7 days (`doneAt`), habit check-ins (`doneThisWeek`, the server's calendar week), goal actions this week from each goal's `recentActions` (the server sends 3 a goal; `actionCount` is all-time, so a goal with all 3 in the week and more on record reads "3+"), sleep/mood days in the last 7; the kcal line only when today has food |
| `BadgeCard` | recent achievements — rendered on Report, not Home |
| `ReminderSuggestionsCard` | suggests reminders from habit/water/wellness gaps; a habit that has its own `reminderTime`, or isn't owed today (`habitDue`), is never suggested. The habit suggestion's time is `suggestReminderTime` (habit-stats.js): the median of the reminder times on the user's other active habits, else 19:00 — the server keeps no time of day for a check-in, so "when they usually tick" isn't knowable. Dropped once that time has passed |
| `GoalTimelineCard` | recent goal actions; `allGoals(sections)` — rendered on Report, not Home |
| `WaterCard` | biggest card (~360 lines). Fish and bubbles are placed by `water-fish.js` (CODEMAP). quick-add (always water), over the goal the big figure counts up ("+500 ml" / "over goal"); no wave at 0% (`.is-empty`); a pour is module state (`pour`: from-pct, target total, start), so it survives re-renders: the server's reply ~60ms after the optimistic render used to draw the final level with no stream. Every render inside the 1.1s window (`POUR_MS`) draws the stream active with a negative `animation-delay` (picked up, not restarted) and the fill where the rise has got to, then moves it to the current level (the rise starts at `RISE_AT` 180ms, after the stream lands; 520ms transition); a re-render with the same total changes nothing, a new total inside the window only moves the target; no pour under reduced motion (fish and bubbles transition `bottom` on the same curve, holding still in the glass); custom amount with a drink picker (`withDrink`, `DRINKS` from `nutrition.js`; `onQuickAddWater(ml, day, drink)`), goal edit with a one-tap suggestion (`suggestWaterGoalMl(weightKg)`: 33 ml/kg to the nearest 250, shown only with a profile weight and when it differs), entry delete; a non-water row reads "250 ml coffee (counts 200)". `consumedMl` is the server's effective total. The fill is full height and slid down with `translateY` (the summary tumblers use `scaleY`, the pour a scaled fixed height): transforms, not `height`, so no layout per frame |
| `FoodCard` | today's food summary, grouped by meal slot (`groupBySlot`; a pre-slot row by its logged hour) with each slot's kcal; a row reads "Idli (2 pieces)" when the entry has `pieces` (the server's FoodEntryResponse doesn't return it yet) else "(120 g)"; an empty slot that has begun offers "Copy yesterday's …" (`onCopySlot(slot)`) only when yesterday had that slot (`copyableSlots`, a Set from app.js `yesterdaySlots()`; null = not known yet, no chips); a fibre/sugar/sodium line only for the figures the day has (`dayMicros`); fibre reads "Fibre 12 of 30 g" (`FIBRE_TARGET_G`, FoodWeek's flat target) |
| `FoodSummaryLink` / `ScreenSummary` | Food screen's link to `SCREENS.summary`; the screen: nutrient thali (4 katoris on the diagonals, kcal in the centre, % geometry so it shrinks on a narrow phone), calorie split bar, Day by day card (tabs flip panels in place, the pick kept in `summaryNutrient`; chart + top dishes per nutrient), water tumblers (the average uses calories' days, `FoodWeek.averaged`: finished logged days, else today; worded "0.9 L on days you logged" since the bars show all 7), diet check. Everything that looks tappable is: a katori, a calorie share or one of Buddy's pills calls `showNutrient(key, true)` (flips Day by day and scrolls to it); a day's bar calls `onPickDay(date)` (the water tumblers are read-only: a tap ran an AI diet check): Buddy's card reads that day (like Money's day panel: `dayFacts` shows kcal, dishes and water from the loaded week at once, the check fills in under it, and "See these meals in Calendar" is the old `onOpenDay` route). The diet check (Check <day> / Check my week; `onCheck(date?)`, `state.dietCheck.{scope,date}`; a Water pill when the server judged water) and the first load wait with `Thinking()`. Colours come from one `--n` per `.is-<nutrient>` in app.css. Headline and pills read the server's `levels`, except that on a low-calorie week a nutrient is "short" only when its gap is deeper than the calorie shortfall explains, and carbs/fat 15+ points over their calorie-share aim count as "heavy" (calories lead the headline: `levels.calories` is the average against the goal, and the server scales each entry's grams to its logged kcal so the two always agree). Data and invalidation live in app.js `loadWeekSummary` / `invalidateWeek` (fetched on open, not at boot: the food week may run an AI estimate) |
| `MiniCalendarCard` | ~370 lines; the day title is `fmtDate(key, 'weekdayDate')` ("Sun, 11 Oct", the app's style); day badges count open, unpaused tasks due that day (+ one-off reminders); the Food section and total hide when `features.food === false` (the in-place repaint passes no features, so it falls back to the module's `homeFeatures`, set by `ScreenDashboard`); also used on Home, styled by `styles/mini-calendar.css`; app.js repaints it in place via `rerenderHomeMiniCalendarIfActive` |
| `HabitSleepInsightCard` | fitness × sleep correlation over **active** fitness habits (a paused one's frozen streak isn't live); a live streak with nothing else to say reads "6 days of fitness: log sleep each night to see the link"; "Habits today" counts Home's owed habits (`habitDue`), not paused ones. **Returns `null`** without at least one fitness habit *and* one sleep entry — it has no correlation to report, and it used to say so at full card size. Callers must guard on the returned node, not on the function. |
| `ScreenFood` | the standalone Food screen; `.gb-food-screen` puts water and meals side by side at ≥1024px, capped at `min(1100px, 100% - 80px)` for a right gutter |

Styles: `styles/app.css` §"Dashboard-specific blocks". Desktop Home is a CSS column flow; after
layout `balanceHome` deals the widget blocks into `.gb-dash-cols > .gb-dash-col`, each to the
shortest column (source order alone left 1280px columns ending 700px apart); one column (phone)
is left alone.
