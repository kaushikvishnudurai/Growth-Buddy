# scripts/notes.js — Notes

Quick jottings with a rich-text editor. Exports `ScreenNotes`, `sanitize` and `shrinkPhoto` (also used by family.js's photo scans). The screen owns
its own list (`onList()` on mount) rather than living in `state` — notes are read here and nowhere
else, so loading them at boot would buy a slower boot and nothing more.

| Piece | What |
|---|---|
| `COLORS` / `colorOf` | the five swatches a note can wear, plus `null` = no colour. Same palette family as habits |
| `ALLOWED` / `DROP` | the allow-list: tag → attributes it may keep. Anything else is **unwrapped** (element dropped, text kept) so a paste from the web loses its markup, not its words. `DROP` is for elements whose text is not worth keeping — unwrapping a `<script>` would paste its source into the note |
| `sanitize(html)` | **the security boundary.** Runs on the way IN (before save) and on the way OUT (before paint), because a note saved by an older build never went through today's version. Walks a `DOMParser` document — inert, nothing executes — rather than pattern-matching a string. `<a>` keeps only `http(s)/mailto/#//` hrefs and gets `rel="noopener noreferrer"`. `<img>` keeps only `src`+`alt`, and only a `SAFE_IMG` src (base64 png/jpeg/webp/gif data URL) — a remote or SVG image is removed outright |
| `textOf(html)` | plain text, for the card preview and the "make a task" title |
| `plainTextOf(html)` | plain text that keeps its lines (`•` / `[x]` / `[ ]` items), for the edit sheet's Share: `navigator.share`, else the clipboard |
| `altOf(file)` / `escAttr` / `searchTextOf(note)` | a new photo's alt comes from its file name (extension dropped, `-`/`_` as spaces, bare "image" gives none). Search reads title + text + every `img[alt]`, lowercased |
| `richEditor({html, placeholder, onInput})` | contenteditable + toolbar. Returns `{node, area, read(), focus()}`; `read()` is already sanitised. Toolbar buttons fire on **mousedown**, not click — by click time the caret has left the editor and the command applies to nothing. A keyboard press (click with `detail === 0`) runs too, and `run()` restores `lastRange` first, since tabbing to the button took the selection out of the editor. `styleWithCSS(false)` keeps `<b>`/`<i>` instead of `<span style>`, which sanitize() would strip. Paste is intercepted and sanitised so what lands is what saves, and the `style` attributes Chrome's `insertHTML` re-adds are stripped right after. A clipboard photo wins only when the HTML beside it has no text: Word/Excel/Notes put a PNG rendering of copied text on the clipboard too. `normalize()` clears the stray `<br>` a browser leaves behind when you delete the last character, which is what lets the CSS placeholder be a plain `:empty` test — no selector can tell one `<br>` from text-plus-a-`<br>`, since `:only-child` ignores text nodes |
| `NOTE_MAX` / `PHOTO_SIDE` / `shrinkPhoto(file)` | photos are embedded in the body as data URLs: each is redrawn on a canvas at ≤1280px, JPEG 0.82 (~200 kB), over white so a transparent PNG doesn't go black. `NOTE_MAX` is `NoteService.MAX_BODY` (2 MB) less 10 kB for the link attributes `sanitize()` adds and is checked as each photo goes in, and on HTML paste |
| `coverOf(body)` | the card's cover: first photo centre-cropped to 2:1 at 640x320 JPEG (25-50 kB), retried rougher if over `COVER_MAX` (60 kB = `NoteService.MAX_COVER`), `''` if it still won't fit or won't decode. Sent as `cover` on every create and update |
| photos in `richEditor` | `addPhotos(files)` is the one path for paste (`clipboardPhotos`: `files`, falling back to `items` for older Safari), drop and the toolbar's "Add a photo" picker. Lands at `lastRange` (collapsed, so it never replaces selected text) and bails if the editor was closed or hidden while the photo shrank. A new photo gets `.is-developing` (the develop-in animation); a clicked one gets `.is-picked` (selected whole, Backspace removes it). Both classes are stripped by `sanitize()` on read. A file drop is always `preventDefault`ed — otherwise a dropped PDF opens over the app. The toolbar's tag button (`describePhoto`) edits the picked photo's alt, else the last one clicked |
| `TOOLS` | bold, italic, underline, strikethrough (`strikeThrough` → `<s>`/`<strike>`), **inline code** (`inlineCode()`: no execCommand, so the selection is escaped into `insertHTML('<code>…')`; a second press on it unwraps via `insertText`; a multi-line selection is refused), H2 and quote (`formatBlock`; second press → paragraph), bullet + numbered list, **checklist**, link, then undo/redo (`stateless`: the browser's own stack, no pressed state). All four new tags were already in `ALLOWED`. A checklist is a `<ul data-checklist>` whose ticked items carry `data-checked` (`checklist()` toggles it on the caret's list; a tap in the item's 28px left padding, where the CSS box is, or Ctrl/⌘+Enter ticks; Enter on a ticked item doesn't hand the tick to the new one). Both flags are in `ALLOWED`, and `sanitize()` empties any `data-` value, so they are flags, never payloads |
| `labelEditor(initial, suggestions)` | the sheet's label chips: Enter or `,` adds (an empty Enter is still Save, so it only `stopPropagation`s when it adds), Backspace in the empty input removes the last, blur commits; a `<datalist>` suggests labels in use. `read()` commits the half-typed one and throws the rule it breaks; `peek()` feeds the unsaved-changes snapshot; `list()` (committed chips, no commit) feeds the edit draft and `set(labels)` restores one; the optional third argument `onChange` fires on every add/remove (the edit sheet's `keepEdit`) |
| `marked(text, words)` / `revealMatch(area, words)` | search highlighting as text nodes + `<mark class="gb-note-hit">` from `splitHighlights` — **never innerHTML** (the text is the user's); `revealMatch` selects the first match in an opened note and scrolls it into view |
| `sheet(...)` | the note's own layout over `openOverlay` from `gb-kit.js` (which owns the overlay contract `a11y.js` looks for). Head row = title + `headActions` (where delete lives, as an icon); footer = Close + primary on one row |
| `colorRow(selected, onPick)` | swatch row; `null` is a real choice and gets a swatch of its own |
| `ScreenNotes` | composer (collapsed to one line until tapped; an unsaved draft is autosaved 800ms after typing via `onSaveDraft` to `note_drafts` (one row per user) and fetched with `onGetDraft` on mount unless typing started first; module-level `composerDraft` is the instant copy for returning mid-session; save / empty close delete both (`dropDraft`), `clearNoteDraft()` from app.js `clearSession` clears only memory), card grid, `NoteCard` (first photo becomes a 150px cover, `+N` chip for the rest, other photos stay inside the note), `togglePin`, `openNote` (edit sheet: title, editor, colour, pin, delete, make-a-task, add-a-reminder, share. **An edit autosaves too**: 800ms after typing or a label change to `{id}/draft` (`onSaveEditDraft`, table `note_edit_drafts`: title, body, colour and `labels`), restored on reopen unless older than the note — labels only when the draft has them (`null` = a row from before they were kept); any save drops it. **Save sends `baseUpdatedAt`**; a 409 opens `askConflict` — save mine over it / load the newer one (reopens the sheet on it) / keep editing. **Delete offers Undo** — `toast.action` → `restoreNote` → `onRestore` (POST `{id}/restore`; the delete is soft)), `sortNotes` (`compareNotes(sortKey)` from notes-core; the sort `<select>` beside search persists to CacheStorage `gb.notesSort`; the Trash keeps the server's order), `paint`. **Views** (`view`: `notes` / `archived` / `trash`, buttons "Archived (n)" / "Trash (n)" from `onCounts`): `inView(n)` says which list a note belongs to, and a save that archives it drops it from this one. **Archive** is a head icon in the sheet that runs `persist(false, {archived})` (same PATCH + 409 path) through the sheet's `commit` (returned by `sheet()`, so `busy` blocks an Escape/backdrop second persist mid-PATCH) with an Undo toast (`setArchived`). Every successful `persist` re-takes the `opened` snapshot. **Trash** cards have no pin, show days left (`trashDaysLeft`), Restore (`restoreFromTrash` → `onRestore`) and Delete forever (`confirmDialog` → `onDeleteForever`); tapping one opens `readOnly`. **Label filter**: `paintLabels()` builds All + one chip per label in use in this list; `activeLabel` ANDs with search, and a note saved from the composer under a filter gets that label. The search box + sort `<select>` are the screen's **top bar** (`.gb-notes-tools`: first child of `.gb-notes`, above the offline banner, composer, views and label chips; `position: sticky; top: 0`, the `.gb-family-sectionnav` treatment; always shown so nothing under it jumps). Search filters on every word, AND, via `searchTextOf` — debounced 150ms, and `filter()` only toggles `hidden` on the cards `paint()` built (rebuilding them re-decoded every cover and blinked). The search text is memoised per note by `createSearchCache` (keyed id+updatedAt), and `highlight()` marks the title and swaps the body for a `snippetAround` the first hit; opening a note from a search lands on the first match. **Offline**: every `paint()` of the main list writes `offlineCopy(notes)` to CacheStorage `gb.notesOffline.<userId>` (`userId` prop; photos stripped, a body still over 200 KB dropped); a load that fails with no status (no network) renders that copy with the "Offline — showing saved copy, editing disabled" banner — composer and views hidden, pins disabled, cards open `readOnly`. A note still wearing its `tmp-` id (created offline, not yet synced) also opens `readOnly` from `openNote` — `onUpdate` refuses temp ids, so an editable sheet could never close and its edit draft PUT to a 404. `clearSession` in app.js removes the copies. `togglePin` holds one request per note; a failed list load offers Try again The list endpoint keeps each photo's alt with its bytes stripped (`NoteDtos.altOnly`), so photo descriptions are searchable without opening a note |
| `_demo()` | the runnable check, Vite DEV only — twenty-one asserts on `sanitize` (incl. checklist flags kept and emptied; `<s>`/`<strike>`, `<blockquote>`, `<code>` kept with attributes stripped and nothing executable inside), `textOf` and `plainTextOf`, (incl. photo kept, photo attributes stripped, remote and SVG images dropped) (scripts dropped, handlers stripped, `javascript:` hrefs removed, links hardened, formatting and lists kept, unknown tags unwrapped, attributes stripped) |

**`document.execCommand` is deliberate** (`ponytail:` at `richEditor`). It is deprecated and
universally implemented; the replacement is "write your own document model over `beforeinput`",
which is a text-editor project, not a feature. The cost is bounded: fixed command set, output
through `sanitize()`, and the fallback if a browser ever drops it is a plain textarea. Photos went in
without one (they are just `<img>` through `insertHTML`). Reach for an editor library when notes
need tables, image resizing or collaboration.

**Rich text means storing HTML**, so `sanitize` is not optional decoration — it is why the body can
be handed to `innerHTML` at all. If you add a tag to `ALLOWED`, add an assert to `_demo()`.

Pure helpers (labels, sort comparator, highlight splitter, search cache, offline copy) live in **`scripts/notes-core.js`**, DOM-free, checked by `node scripts/notes-core.test.mjs`.

Backend: `/api/notes` (list — `?archived=true` for the Archived view —, `trash` GET, `counts` GET, GET `{id}`, POST, PATCH `{id}` incl. `labels` + `archived`, DELETE `{id}` (to the Trash), DELETE `{id}/forever` (Trash only), POST `{id}/restore`; `draft` GET (204 = none) / PUT (empty deletes) / DELETE) → `note/NoteService`, labels through `NoteLabels` (10 × 30, enforced there), the Trash purged nightly past 30 days (`DataCleanupJob` → `purgeTrash`)
(soft delete; `""` clears a colour where `null` means "leave it alone"; 2 MB body cap). **List, POST and PATCH return the body with its photos cut out** (`bodyTrimmed`), plus `cover` and `photoCount`; `openNote` fetches `GET {id}` (`onGet`) before building the sheet whenever `bodyTrimmed` is set — editing the trimmed copy would save it back and delete the photos. The card shows `.is-opening` while that loads, and a placeholder cover (`.is-empty`) for a photo note with no saved cover,
covered by `NoteServiceTest`. Wiring: `SCREENS.notes` in `app.js`, `NAV_CATALOG` in `gb-kit.js`,
the "Note" row in the quick-add sheet, and the `notes` feature toggle in `FEATURE_DEFS`.
"Add a reminder" hands the text to the calendar via `prefillCalendarReminder` rather than growing a
second reminder form. Styles: `app.css` §"Notes — composer, rich-text editor, sticky cards".
