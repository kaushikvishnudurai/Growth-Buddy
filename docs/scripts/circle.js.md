# scripts/circle.js — Growth Circle

Exports `ScreenCircle`. People search + mentorship invites + circle challenges. Repaints its
own subtree (`paint()`). `refreshAll` is the ONLY loader: it awaits outgoing and
incoming together and paints once. Loading them separately made the screen paint twice with half
the data and visibly jump, so don't reintroduce per-list refreshers. A later failed load keeps the
lists it has; a failed FIRST load (no cache yet) paints `paintLoadError` — "Could not load your
mentors and requests." with Try again — instead of the empty state, which hid waiting requests.

| Piece | What |
|---|---|
| `sectionSkeleton(rows)` | shimmer rows every section starts with. All three (Connections, Your invites, Challenges) used to render empty and then jump when their fetch landed |
| `PersonRow` | one person; returns `null` for `relationship: 'self'`. The two mentorship directions are INDEPENDENT, so it renders a slot each from `person.mentorLink` / `person.menteeLink` (`active` → status pill, clickable on the `mentorLink` side only, `pending` → pending pill, `none` → invite button). You can mentor someone *and* be mentored by them. |
| `showPartnerStatus` | a MENTEE's progress sheet, for their mentor. **One direction only** — a mentee gets no window on their mentor, like a manager seeing a report's board and not the reverse. `/connections/{id}/status` 403s the mentee side (`PartnerStatusAccessTest`), and the mentee can switch it off entirely in Settings → Account → Privacy (`shareProgress` in ui_prefs). The rows and the `mentorLink` pill just don't offer the tap; a refused load prints the server's message in the sheet's subtitle |
| `checkedToday` / `paintCheckPill` / `CheckPill` | the mentor's "Checked today" tick. `checkedAt` is stamped SERVER-side (`MentorshipService.markChecked`, called when the progress sheet loads) and compared against the reader's LOCAL day here — so no nightly job has to expire anything. `paintCheckPill` writes in place so opening the sheet flips the pill without a repaint |
| `statusLabel` / `STATUS_LABELS` | `pending` → "Invite pending", `accepted` → "Connected", `rejected` → "Declined" |
| `RequestRow` | a PENDING invite addressed to me, with Accept / Decline (`onRespond`, the same endpoints as the bell). Painted into `requestsEl`, the "Requests for you" card above Connections, which renders nothing at all when there are none |
| `OutgoingRow` / `IncomingRow` | request rows with revoke / accept. On an accepted row the caller can open (i.e. a mentee's), the check pill REPLACES the "Connected" status pill — inside a card headed "You mentor", "Connected" says nothing the heading doesn't |
| `localISO` / `shortDay` | the reader's local day as `YYYY-MM-DD` (date inputs, upcoming checks: string compare orders them) / a short weekday label |
| `askNudge` | Cheer / Nudge form (optional line, 140 chars) → `mentorshipApi.nudge`. The server caps it at 3 a day per sender per link (429), and the form's toast shows that message |
| `openChat` | the thread sheet for one accepted link: `role=log` + `aria-live=polite`, newest 50 then "Load older" (`?before=` the oldest held), composer (Ctrl/Cmd+Enter sends). Partner lines arrive live via `gb:mentorship-message` (app.js re-dispatches the server's transient `mentorship_message` frame), deduped by id; the listener goes in `openOverlay`'s `onClose`. Cheers/nudges show as centered event lines |
| `WeekCard` | the mentor's "This week": the mentee's check-ins Monday to today (their zone) vs last week, and top-5 streaks. `shared: false` (mentee's progress sharing off) shows only a one-liner — the server never sends the numbers |
| `AgreementList` | one link's agreement as a checklist: tick, add, remove, each saving the whole list (`PUT {id}/agreement`, last writer wins; `latestSave()` from circle-core.js lets only the newest save's outcome repaint: an older save failing after a newer one is ignored, the newest failing shows the last list the server accepted). Stored as text in the existing 500-char column, one item a line with `[x] ` / `[ ] ` (`parseAgreement` / `formatAgreement` in circle-core.js); a pre-checklist agreement reads as one open item |
| `LinkExtras(links, …)` | under every connection (`gb-conn-item` wraps row + extras): one `AgreementList` per link, Cheer / Nudge / Message, and, when I mentor them, This week (refetched on every open). On a phone the four tools stack icon over label to share one row |
| `openSearchModal` | find-someone modal: `paintLoading` / `paintEmpty(msg, onRetry)` / `paintList` / `loadPeople`, plus browse. `paintList` drops `currentUserId` — the single choke point every list passes through, so you can never invite yourself. The typed search stamps each keystroke with `seq`; a server answer for an older query is dropped |
| `openFormModal` | generic field-list modal; field types text/number/date, `checkbox`, and `select` (`options: [{value, label}]`); optional `presets: [{label, values}]` = one-tap chips that fill fields (submit still sends) |
| `SeatRing` | the circle drawn as its members: a seat each around a ring (`seatLayout`), the name in the middle in the display face, "3 of 4 in today" in mono. A seat is lit (checked in today, their own today), ash (not yet) or dashed (keeps progress private, `doneToday: null`); `seatOrder` groups them lit → ash → private so the track's fill (lit / all seats, started half a seat early inside the SVG) covers exactly the lit seats. Another member's seat is a button that cheers them; `is-cheered` (a small sun) comes from the server's `cheeredByMe`, so a reload never offers a cheer the once-a-day limit would refuse. Over `MAX_SEATS` the last seat reads "+N". Seats light in turn once (`is-on` after two frames); reduced motion skips it |
| `showJoined(joined)` | every join (code, link, Browse) ends here: the card is added with `offerTemplate` (or the existing one found by `data-circle-id`) and scrolled into view (`auto` under reduced motion); Browse's sheet closes on a join. With `offerTemplate`, `circleCard` shows `templateOffer` while nothing is active or upcoming: Start `CHALLENGE_TEMPLATES[0]` today in one tap, or Pick another (the full form) |
| `circleCard` | head (member count, New challenge, ⋯), the ring, **one line to act on it** (`paintNudge`: "Cheer Priya on" / "Cheer the 3 still to check in", one tap cheers each, a refusal skips that one; else "Everyone's in today." and its siblings), the challenges (the active one first; none → one line + Start a challenge), then posts — open at once on the first card (`openPosts`), "Show posts" on the rest. The board is read, not tapped: mono ranks (a tie shares the number), no medals, no per-row cheer (the seats do that), dates in words via `challengeMeta` ("Day 1 of 7 · ends Sat 17 Oct") |
| `ChallengesPanel` | circle challenges (`wins` = the share-a-win source): `METRICS` / `metricOf` (label, unit and empty text per `metric`; no metric = habit check-ins), `leaderboardRows`, `challengeBlock` (Active / Upcoming / Ended; says how many members keep progress private — `hiddenCount`), `startChallenge` (what counts + a start date, today or later), `newCircle` (Private checkbox → `visibility: 'private'`; a pre-ticked "Start a 7-day habit sprint today" creates `CHALLENGE_TEMPLATES[0]` right after, and the "Circle created." toast carries **Invite** → `shareInvite`, since the share sheet needs a gesture of its own), `joinWithCode`, `circleCard`, `addCard`, `removeCard`, `refresh`, `openBrowse` (holds the join-with-code button, since private circles are never listed). An action touches only its card: a new challenge reloads that card's list, a new or joined circle is appended (`addCard`); `refresh` is the initial load and the error retry only |
| `openCircleMenu` / `openMembers` | the card's ⋯ sheet: the private code (members only), **Share invite link** (`shareInvite`), Members (a cheer button on everyone else; owner also: Make owner / Remove), and Leave — or Delete for the owner, who can't leave |
| `shareInvite` / `joinFromLink` | the invite link (`inviteLink` on `api.siteUrl`, the public site from app.js `publicSiteUrl()` — never `location.href`, which in the phone app is `https://localhost`: `#/circle?join=CODE` for a private circle, `#/circle?circle=<id>` for a public one) through the OS share sheet, else the clipboard. Opening one asks first ("Join this circle?" `confirmDialog`; a crafted link used to join whoever opened it): `joinFromLink` runs after the first `refresh()` (so the list doesn't paint over the new card), strips the query, confirms, then joins. Join with a code carries a pre-ticked "Add <goal> to my habits" (`goalField` / `adoptGoal`), through the `addHabit(name)` prop (app.js `addHabitNamed`: a plain daily habit, resolves false when one of that name exists) when the goal fits a habit name (120 chars). `screenFromHash` routes on the part before `?`, and `landAfterSignIn` keeps the query, so a link opened signed-out still joins after sign-in |
| `cheerButton` | starts sent and disabled when the member's `cheeredByMe` says today's cheer is used (as the seats do); one tap → `POST /{id}/members/{userId}/cheer`, a bell card ("X is cheering you on"). On active-challenge leaderboard rows and the member list, never on yourself. Server: once per pair per day + `CHEERS_PER_DAY` (10) per sender, `RateLimiter` peek/record so refusals don't count |
| `PostsFeed` / `PostRow` / `RepliesThread` | the circle's posts, opened by the card's Posts button (lazily — one fetch per opened card): **"Share a win" chips** (`wins()` from app.js hands over the lines, or their inputs and circle.js runs `winLines` (`circle-wins.js`) on them: streaks of 3+ ("Week N" for a weekly cadence), a goal done this week, every habit due today ticked; a tap fills the box, Post sends), composer + newest 50 + "Load older" (`?before=` the oldest held; a failed older page toasts and keeps the posts shown, only a failed first load shows "Could not load posts" + Try again). Each post: a kudos toggle (`gb-kudos`, `aria-pressed`; one per member, server-enforced by the `(post_id, user_id)` key), a **replies** toggle with the count (`RepliesThread`: fetched on first open, oldest first, capped at 100, Enter sends; author or owner deletes, with Undo (`removeReply`: the row goes at once, the DELETE is sent when the 6 s toast has passed); a reply rings the post's author, never yourself; 30 per sender per hour) and, for its author or the circle's owner, delete |
| `circle-core.js` | the pure parts, checked by `node scripts/circle-core.test.mjs`: `CHALLENGE_TEMPLATES` (Start a challenge's one-tap picks), `standingLine` (the line over a board: "You're #2, 3 check-ins behind Priya." / "You lead by 2" / an ended one names its winner), `inviteLink` / `inviteFromHash`. `winLines` lives in `circle-wins.js` (same test) so app.js can import it at boot without pulling this file in |
| `openSheet` | bottom sheet wrapper |
| `openNoteModal` / `promptAndSend` | send an invite with a note |
| `revokeAndRefresh` | revoke an outgoing request |
| `launchSearch` | entry point from the header |

Backend: `/api/mentorship` (requests, accept/reject/revoke, incoming/outgoing, connection status;
and `MentorshipChatController`: `{id}/nudge`, `{id}/messages`, `{id}/agreement`, `{id}/week`, where
`{id}` is the accepted request's id), `/api/circles` (mine, join/leave, posts + kudos + delete,
replies (`posts/{postId}/comments`), member cheers, challenges), `/api/users/search|browse` for the people list. Wired in app.js as `mentorshipApi` and
`challengesApi`. Challenge ranking is by the challenge's `metric` (`ChallengeMetrics`: habit check-ins,
focus minutes, water-goal days); members with `shareProgress` off are left off the board
(`ProgressSharing`, the switch the mentor window and the weekly card read).
**Live:** the screen listens for `gb:circle-changed` (app.js re-broadcasts every mentorship push)
and runs `refreshAll`; the listener retires itself once the screen has been mounted and is gone.
Server-side, `MentorshipService.checkCanInvite` refuses an invite on a side that is already
accepted or pending (either sender — the mirror case), and for 7 days after the other person
declined; declined/cancelled rows drop out of the lists after 7 days (`visible`).
**Screen order is importance:** Requests for you (nothing when none), Your circles, then Mentorship (`section()`; one quiet line when there are no connections, and "Invites you sent" only when there are some). It used to open on Mentorship's two empty cards with the circle below the fold. `.gb-circle-section` keeps a 112px reserve elsewhere; this screen drops it.
`paint()` groups accepted links by person, then splits them into **Mentor each other**, **You mentor**
and **Who mentors you**, by the same rule the rows use for the progress window (an offer you sent, or
a request sent to you, makes you the mentor). A mutual pair is ONE entry (`MutualRow`: progress opens
from the link where I mentor) with two checklists ("You help X with" / "X helps you with", each with
its own End) and one toolbar. Its Cheer / Nudge / Message use the link with the smaller id, so both
partners land on the same thread; messages already on the other link stay there, unshown. Empty
groups are skipped; no connections at all still falls back to the single empty card.

Styles: `app.css` §"Circle (person rows + status pills)", `.gb-conn-group` + `.gb-check-pill`, §"Search modal",
the "Circle: Requests for you, the card's tools/feed" block after `.gb-browse-row`, then the kudos /
connection extras / weekly card / chat sheet block right after `.gb-circle-code`,
§"Circle challenges + leaderboard".
