# scripts/report.js — Report screen

Exports `ScreenReport`. A progress overview that opens on one **Today** card (score, tasks,
habits, top streak, water, calories; `.gb-report-grid--wrap`, three tiles a row) and then
Insights. A switched-off feature drops its tile and its later sections; there is no in-report
"turn it back on" prompt any more (Settings has the toggles).

| Piece | What |
|---|---|
| `focusCard(focus, habits, onMakeHabit)` | "This week's focus", first on the screen: `weekFocus(weeklyReviews)` (review.js: the latest weekly review filed this week or last) with **Make it a habit** (`onMakeHabit(name)`, hidden when a habit of that name exists or the prop is absent). Nothing when there is no focus. app.js passes `weeklyReviews` (state.weeklyReviews) and `onMakeHabit` (`addHabitNamed`, then `repaintReport`) |
| `insightsSection(data, {loading, onDismiss, onAction})` | renders `buildInsights(data)` from `scripts/insights.js`. `ScreenReport` passes `yearOf(...)` trends + wellness (the year once it lands), money, habits, tasks, flattened goals, `goalProgress`, `insightHistory` as `history`, `features` and `dismissedInsights` (`ui_prefs.insightsDismissed`, last 50, written by app.js `onDismissInsight`). Each card shows "Based on …" (`basis`) and a dismiss ✕, plus its `action` as a `.gb-insight-action` button when `onAction` (`ScreenReport`'s `onInsightAction` = app.js `runInsightAction`) is passed. Empty: a skeleton while `insightLoading`, else "N of 7 days logged" + a progressbar (`insightProgress`) |
| `shortDay(k, weekday?)` | "22 Sep" / "Tue, 22 Sep" for the charts and pixel readout; en-GB's Intl "Sept" is cut to "Sep" like the rest of the app. Month ticks use `MONTH_SHORT` |
| `statTile(label, value, sub)` | a `null`/`NaN` value renders as a dash (Today's Tasks tile with nothing due: dash + "none due today"; Calories with nothing logged: dash + "Not logged"). The Tasks tile counts home-order.js `tasksForToday` (due by today + done today), the same set as Home's Today card and the score — not the whole open list. Values are Space Mono in ink; no per-metric colour (text never wears a series colour) |
| **hand-rolled SVG charts** | `svgEl`, `trendChart(values, color, days, fmt, title, opts)` (the SVG is `aria-hidden`, a `.gb-sr-only` table with a summary caption carries the data; `opts.bucket: 'week'` makes each point a week's daily average keyed by its Monday — summary, table header and tip say "week of" — and `opts.ticks` `[{i, label}]` prints month labels under it, `.gb-trend-ticks`, edge labels hang inward), `trendCard(..., vs, opts)`: the head shows the change (`vs.amount` + `vs.label`, mono, ink), or the latest value when there is no `vs`; with a `vs` the chart draws the period before's average (`opts.baseline`) as a `.gb-trend-base` hairline keyed under the chart (`.gb-trend-basekey`, beside `opts.sub`) and labels the latest value at the line's end (`.gb-trend-end`, down-left when the line falls into the dot). All in `.gb-trend-canvas`, the box the % positions are relative to. No chart library. Hover/drag shows one day's value via `.gb-trend-tip`, snapped to the nearest logged day. `pointerleave` hides it for a mouse only: on touch it fires right after the lift, so a tap's readout stays until the next tap or a scroll. The Calories and Water series drop 0 (not logged) like `vsLine` does. `vs` = `{dir, amount, label, prev, baseName}` |
| `SCALE_NUM` / `SCALE_LABEL` | categorical check-ins → 1–4 and back (`low/poor`=1 … `great`=4) |
| day helpers | `pad2` (from `dates.js`), `localKey` (from `review.js`), `lastNDays(n)`, `nDays(n)` |
| `summarize(values)` | latest + delta for a trend card |
| `rangeToggle(range, onRange)` | 7 / 30 / 90-day / 1-year switch (`state.reportRange` 365; 90 needs the year fetch for its "vs the 90 days before") |
| `trendsSection({on, trends, wellness, range, onRange})` | the drill-down. Each card carries **"vs last week"** (`vsLine` → `periodDelta`): the last `range` *full* days against the `range` before them. Today is excluded from both — half-logged, it read as a drop every morning. kcal 0 = not logged. The **Daily score** card plots the same `curDays` (finished days, today left out) for its line, headline and avg: today's still-climbing score ended every line in a drop. **1 year**: the local `card` wrapper buckets the 365 daily values with `weeklyBuckets` and labels every other month (`monthTicks(keys, 3)`, counted back from this one); the headline is the latest **weekly** value (a daily "Good" over "latest weekly average Okay" read as two answers), the avg line stays daily and there is no vs line (the year fetch holds no year before). Mood/sleep `fmt` rounds, so a weekly average still reads as a word |
| `weekRollupSection({on, trends})` | **This week vs last**: a visible `<table class="gb-wow">` (sr caption) of water ml/day, kcal/day and protein g/day (`proteinG`, shown only when some day carries it) from `weekOverWeek`: Monday→yesterday against the full week before, per-day average over logged days, 0 = not logged. Gated by the water/food features; omitted when neither week logged anything |
| `compareSection({on, trends, wellness, money, insightHistory})` / `scatterChart(res, mx, my)` | **Compare**: two `<select>`s over `COMPARE_METRICS` (sleep hours, mood, energy, stress, water, kcal, spend, focus minutes, habit %; feature-gated). Series come from insights.js `signals()` (water 0 dropped), `focusMinutesByDay(insightHistory.focus)` and `pixelValues('habits')` ×100. Every ordered pair is run through `correlate(..., {min: 14, before: today})`; only metrics with a ≥14-day partner are offered, Y only lists X's partners, a stale pick falls back to the first valid one. Shows a scatter (points `--brand` 0.55 with a surface ring, recessive `.gb-scatter-axis`/`.gb-scatter-tick`, nearest-point tip), `r` + N days, `correlationWords` and an "association, not a cause" line; `.gb-sr-only` table of the days. Until the user picks (`comparePicked`), it opens on the pair with the largest |r|. Pick is module-level (`compareX`/`compareY`), not app state. No pair → an empty-state card explaining the 14 shared days |
| `pixelsSection` / `pixelGrid` | **year in pixels**: a row per month for the last 12 (oldest on top) x 31 day columns, shade = `pixelValues(metric)`, blank = nothing logged, outline = a day still to come. Tapping a day reads it out under the grid (`.gb-pixels-readout`, aria-live, one delegated listener); the grid is a focusable `role=group`, arrow keys walk the pick (left/right by day, up/down by month), Home/End jump to the first/last day, Escape clears; otherwise that line is the year's summary. Legend words come from `PIXEL_METRICS` (`low`/`high`). Readout values: `pixelFmt` per metric, mood as a word per day and "2.7 of 4" averaged (it is a 1-4 check-in, not a %), score/habits as %. **Today's score is blank** (still climbing; as a finished day it read as 0%), and `monthReview` averages finished days only. Score / Mood / Habits toggle repaints in place (`pixelMetric`, module-level, not app state, not persisted) |
| `yearOf(trends, wellness, insightHistory)` (lives in `outlook.js`, imported here, so Home's Outlook ranks the same days) | boot holds only 60 days of daily logs; Report fetches 366 (`insightHistory.year`) and insights, trends, pixels + records use it once it lands. **Merged**, live stores winning a shared day (they hold today's edits); sleep is included. The server's finished-day scores replace those days' snapshot scores even without the year: `insightHistory.scoreRange` (`GET /api/score/range`, `[{date, score}]`, the year; filled only once app.js `loadInsightHistory` fetches it) and `insightHistory.scores` (the two days before today, which win a shared day). Every other past score is the snapshot from the last time the app was open that day, so a day never opened has none |
| `recordsSection` | `personalRecords` tiles (money in lakh grouping for ₹ only, the device's grouping otherwise) + **Share my month** (`monthReview` → `share-card.js`; its sub says "average daily score over N days", the scored days it stands on; the button opens a preview sheet, `renderStoryCard` as an `<img>`, with Share / Cancel); on the 1st–3rd it shares **last month** (`reviewMonth`). Section is omitted when both are empty |
| `ScreenReport({...})` | assembles all sections |

The look-back maths (pixels, records, period delta, month card, `weeklyBuckets`, `monthTicks`, `correlate`, `correlationWords`, `focusMinutesByDay`, `weekOverWeek`) lives in **`scripts/review.js`** — pure,
no DOM, checked by `node scripts/review.test.mjs`. Habits on the pixel grid (and Compare) only reach back as far
as the habit history Report loads (60 days), and each habit counts from its first done day on or after `since`, so the days before it got going are blank, not 0%.

Data is local: `trends` and `wellness` come from the client-side stores in app.js (hydrated from
`/api/daily-logs?days=60` at boot). `insightHistory`, which app.js `loadInsightHistory` fetches when
Report opens (at most every ten minutes after a fetch that got anything back; a failed one is retried on the next render, one request in flight at a time), arrives after the first paint: insight cards, records and
the full year of pixels that need it appear on the re-render.
Styles: `app.css` §"Report screen" (note base `.gb-card` has no padding, so report cards
inset their own content), §"Insights", §"Report — trends drill-down" (also the 1-year ticks, Compare and This week vs last), §"Report — period comparison,
personal records, year in pixels" (end of file).
